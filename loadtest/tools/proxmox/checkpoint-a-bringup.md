## 0. The template was broken — cloud-init never ran

The `trussal-sut` template is a **Debian 12 genericcloud** image, but in these
clones cloud-init does **not** execute (confirmed: `ssh.service` fails at boot for
lack of host keys; the static IP / `trussal` user / injected key never applied;
`qm cloudinit dump` shows Proxmox's NoCloud data is *correct*, so the datasource
just isn't being consumed in the guest). Rotating the instance-id
(`qm set --cipassword … && qm cloudinit update && qm stop/start`) did **not**
help — cloud-init is genuinely inert in that image.

**Fix the disks offline with libguestfs** (Proxmox host has no subscription, so
first swap the enterprise apt repo for `pve-no-subscription`, then
`apt-get install -y libguestfs-tools`). Per VM, one line:

Pick a throwaway password for the isolated staging VMs and export it first
(`LAB_PW=$(openssl rand -base64 12)`); it is only ever used on the LAN console
and is never the SSH path (key-only). Do **not** commit a real value.

```bash
lvchange -ay pve/vm-1201-disk-0 2>/dev/null; LIBGUESTFS_BACKEND=direct virt-customize -a /dev/pve/vm-1201-disk-0 \
  --hostname sut-explicit --root-password "password:$LAB_PW" \
  --run-command 'id trussal >/dev/null 2>&1 || useradd -m -s /bin/bash trussal; usermod -aG sudo trussal' \
  --password "trussal:password:$LAB_PW" \
  --ssh-inject trussal:string:'ssh-ed25519 AAAA… trussal-test-key-2' \
  --write '/etc/sudoers.d/trussal:trussal ALL=(ALL) NOPASSWD:ALL' --chmod 0440:/etc/sudoers.d/trussal \
  --run-command 'ssh-keygen -A' \
  --run-command 'set +e; systemctl enable ssh systemd-networkd systemd-resolved networking; true' \
  --run-command 'printf "[Match]\nName=eth0 en*\n\n[Network]\nAddress=192.168.1.41/24\nGateway=192.168.1.1\nDNS=192.168.1.1\n" > /etc/systemd/network/60-static.network' \
  --run-command 'rm -f /etc/resolv.conf; echo "nameserver 192.168.1.1" > /etc/resolv.conf' \
  --run-command 'touch /etc/cloud/cloud-init.disabled'
qm start 1201
```

Notes that cost time:
* This image has **no `ifupdown`** (`networking.service` doesn't exist) — it's
  `systemd-networkd`. Writing only `/etc/network/interfaces.d/*` does nothing;
  you need `/etc/systemd/network/*.network`. `systemctl enable networking` must
  be allowed to fail (`set +e`) or `virt-customize` aborts the whole run.
* The image is **minimal**: no `git`, `docker`, `node`, `make`, `g++`, `tc`,
  `jq`, `ca-certificates`. `sudo` *is* present. `PasswordAuthentication no` in
  sshd — so console login needs `root` + `$LAB_PW`, and SSH needs the key.
* The matching private key is `~/.ssh/trussal-test-key-2` on the workstation
  (`192.168.1.134`). Connect with
  `ssh -i ~/.ssh/trussal-test-key-2 -o IdentitiesOnly=yes trussal@192.168.1.41`.

**For the Checkpoint-B hash SUT:** rebuild the template so cloud-init works
(import a fresh `debian-13-genericcloud-amd64.qcow2`, `qm set --ciuser/--sshkeys/
--ipconfig0`, boot once to verify `cloud-init status` is `done`, then
`qm template`). Don't ship the broken one again.

## 1. Deploy Trussal onto the SUT (`.41`)

Not the prod `./run.sh` — that FATALs unless `CONFIG` points at a pre-seeded
tree outside the repo. Use the **`dev:setup` path**, which is built for exactly
this (standalone stack, repo-local gitignored `docker-jitsi-meet/.jitsi-meet-cfg`,
`web` binds host `80`/`443` directly).

`loadtest/tools/proxmox/` ships `sut-bringup.sh` (generated by the harness
session) which does all of it. Copy it over and run detached:

```bash
scp -i ~/.ssh/trussal-test-key-2 sut-bringup.sh trussal@192.168.1.41:~/cpa-sut-bringup.sh
ssh -i ~/.ssh/trussal-test-key-2 trussal@192.168.1.41 \
  'chmod +x ~/cpa-sut-bringup.sh && nohup ~/cpa-sut-bringup.sh > ~/cpa-bringup.log 2>&1 &'
# then poll ~/cpa-bringup.log for "DONE." / "FATAL:"
```

What it does, in order:
1. `apt-get update` + `ca-certificates curl gnupg git make g++ jq iproute2 rsync`
2. Docker CE (`docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`) + `usermod -aG docker trussal`
3. Node 20 via NodeSource (`setup_20.x`)
4. `git clone` the repo → `git checkout main && git pull --ff-only`
5. `export JAMULUS_HOST=jamulus.trussal.com` then `npm ci --include=dev`
6. `npm run dev:setup` — creates `docker-jitsi-meet/.env` from `env.example`,
   `CONFIG=./.jitsi-meet-cfg`, `gen-passwords.sh`, seeds `web/body.html` +
   `web/nginx/custom-routes.conf`, builds the bundle
7. Patch `.env`: `PUBLIC_URL=https://192.168.1.41`, `ENABLE_LETSENCRYPT=0`,
   `ENABLE_HTTP_REDIRECT=1`, **`ENABLE_P2P=0`** (harness requirement — all media
   on one JVB), `ENABLE_XMPP_WEBSOCKET=1`, `COLIBRI_REST_ENABLED=1`,
   `JVB_ADVERTISED_IPS=192.168.1.41`, `DOCKER_HOST_ADDRESS=192.168.1.41`,
   `RESTART_POLICY=no`
8. `node build.mjs --deploy` then
   `docker compose up -d --build web prosody jicofo jvb latency`
   (skips `ddns`, `coturn`, `jamulus-relay` — not needed for the smoke)
9. verify (see §2)

Later, for Phase 2 (not the smoke): the 5 music-mode audio vars (memory
`music-mode-env-vars`), and `SIDECAR_CONTROL_TOKEN` on `.41` == the bots VM's
`FLEET_CONTROL_TOKEN` or no aggregator/fleet spawns.

## 3. Workstation — smoke it

The workstation `.venv` has the analysis deps (pandas / matplotlib / pyarrow /
websocket-client / pyyaml) but **not** locust or playwright — enough for
preflight's sidecar handshake, the observer, and ingest→figures. Real media
endpoints (`media_agent.py`) and locust run from `.42` later.

```bash
cd ~/Trussal/loadtest
export LOADTEST_PY=.venv/bin/python

# a. preflight — ssh checks to .41/.42 need the key on your agent
#    (ssh-add ~/.ssh/trussal-test-key-2); the line that must pass is
#    "sidecar handshake: ok"
bash orchestrate/preflight.sh config/inventory.checkpoint-a.yaml

# b + c. observer + synthetic players, one self-contained driver.
#    A real browser join does NOT work against this SUT: HTTPS gives an
#    unscriptable self-signed-cert interstitial, and plain HTTP from a
#    non-localhost origin is not a secure context so Jitsi bounces to
#    /static/webrtcUnsupported.html (no RTCPeerConnection). The campaign's
#    ghost_ws clients never use a browser either — they are role=player
#    WebSocket clients (harness/sidecar.py SidecarClient), which drive the
#    exact observer code paths (peer-join / peer-update / peer-leave / roster).
#    tools/proxmox/cpa-smoke-driver.py spawns collectors/sidecar_observer.py as a
#    subprocess and runs 3 such players: worsening WWAN metrics stepping every
#    25s, escalating code_payload() across media kinds, one involuntary drop
#    (sc.close(intentional=False)) at +48s and two clean leaves.
RUN_ID=cpa-smoke OBS_S=120 RUN_S=95 .venv/bin/python tools/proxmox/cpa-smoke-driver.py

# d. analysis end-to-end: ingest -> parquet -> figures
.venv/bin/python analysis/ingest.py  results/cpa-smoke   # raw/*.jsonl -> tidy/*.parquet + campaign.db
.venv/bin/python analysis/metrics.py results/cpa-smoke   # summary/timeseries/dropout_rate parquets
.venv/bin/python figures/render_all.py --run results/cpa-smoke --column single
ls figures_out/     # 10 fig*.pdf + .png; all _SYNTH for a smoke (no S1-S6 cells)
```

The smoke has **no manuscript-scenario data** (only S0 sidecar-observer roster
metrics), so every figure correctly falls back to its watermarked synthetic
reference. Two figure-robustness fixes landed while proving this path:

* `figures/render_all.py` — one figure raising no longer aborts the batch; it
  prints `FAILED <mod>: <err>`, renders the rest, and exits non-zero.
* `figures/_data.py::ensure_scenarios(frame, scenarios, synthetic_loader)` —
  a run that only touched an S0 cell still writes a non-empty `summary.parquet`,
  so `is_synthetic` was False and fig01-08 rendered **blank, unwatermarked**
  axes. The guard swaps in the synthetic reference when the real frame carries
  no row in the scenarios that figure plots. Wired into fig01-06 + fig08;
  fig05 also self-guards its `bars_per_group == 0` divide.

**Not yet wired (Phase 1):** a human/browser participant that drops emits only
`peer_leave` with a roster decrement — `analysis/metrics.py::dropouts()` only
classes a departure involuntary from an explicit `dropout`/`disconnected`/
`agent_crash` collector event or a *bot* `peer_leave` with no nearby operator
remove. `SidecarClient.close(intentional=False)` sets no wire flag the observer
can see. The bot heuristic (a `peer_leave` with no matching planned-leave event
from the load generator within a window) needs porting to human peers.
